개발 인계

기준 문서현재 범위와 제품 구조실행과 원본서버 구현 우선순위채팅과 사용자 안전문의와 운영 알림메이트 등록과 재심사공개 요청지도와 장소선택 해제와 재모집검증과 출시예약번호MVP 예약 취소·수수료 전액 반환

현재 홈페이지 MVP의 개발 진입 문서입니다. 제품 정책을 다시 복사하지 않고 화면 명세와 구현 계약의 원본으로 연결합니다. 실제 인증·서버·PG·이메일 발송은 미연결입니다.

기준 문서

  • MVP 운영 정책: 예약·취소·반환·노쇼·심사·탈퇴.
  • 알림 정책: 사건별 수신자·트리거·문구와 8절 개발 구현 기준. 대상 ID, 결제·만료 경합, 발생 당시 문구 보존, 활동 제한 계정 접근을 확인합니다.
  • 화면별 기능 명세: 기존 B-* ID별 입력·행동·예외.
  • 디자인 시스템: 공통 UI·토큰·아이콘.
  • 출시 전 미확정 사항: 사업자·법률·VAT·개인정보 보존 등. 제품 정책과 구분.

현재 범위와 제품 구조

고객과 메이트는 하나의 홈페이지·계정을 사용하며 승인된 메이트만 모드를 전환합니다. 운영자는 별도 웹을 사용합니다. 활성 화면은 32개이며 화면 번호를 재배정하지 않습니다.

여행자 하단 메뉴: 발견 / 내 여행 / 메이트 / 채팅 / 마이. 메이트 하단 메뉴: 여행 찾기 / 내 활동 / 채팅 / 마이. 루트 화면은 큰 상단 바를 중복 표시하지 않고 상세 화면은 돌아가기 경로를 제공합니다. 마이는 프로필·메이트 등록·설정 중심이며 설정에 알림·차단·언어·계정 메뉴를 둡니다.

장소 보관함과 날짜별 여행은 분리합니다. 여러 여행·여러 날 요청·날짜가 겹치지 않는 복수 요청을 보존합니다. 외부 예약은 링크만 제공하며 예약 기록 양식, 체류시간·방문시각 계산, 후기, 휴무 달력, 별도 정산 화면, 앱·브라우저 푸시는 MVP에서 제외합니다.

호환 경로: planner → trips, review·upcoming → booking, guide-calendar → guide-activity, guide-earnings → guide-fee. 이전 저장 필드와 localStorage 키는 보존하되 제외된 기능을 활성 기능으로 안내하지 않습니다.

실행과 원본

  • 한국어 홈페이지 / 영어 홈페이지 / 운영 웹 / 화면 탐색.
  • src/assets/app.js: 한국어 기능 원본. tools/i18n과 build_english.py로 영어 생성. 영어 생성물을 직접 수정하지 않습니다.
  • src/assets/catalog.js: 화면 ID와 명세. src/assets/access.js: 시연 권한. src/assets/design-system.css: 공통 UI.
  • docs/mvp-policy.html의 원본은 tools/templates/mvp-policy.html. 알림 기준 원본은 docs/notification-policy.md. 문서 생성은 tools/scripts/build_docs.py, 화면 탐색 생성은 build_frontend_index.py.
  • archives/는 동결 백업이며 수정하지 않습니다. 브라우저 file:// 저장과 localhost 저장은 자동 공유되지 않을 수 있습니다.

서버 구현 우선순위

  1. 인증·계정·역할·본인 소유권 검사와 닉네임 고유 제약. NFKC·공백 제거·소문자 기준이며 저장 직전 원자적 중복 검사.
  2. 개인 여행과 공개 요청 스냅샷 분리. 제안 버전·예약 금액·일정 고정. 예약 선택 시 날짜 확보와 요청 상태 변경을 하나의 트랜잭션으로 처리.
  3. 선택된 메이트의 PG 주문·금액·통화·서명 검증 후 확정. 중복 결제·취소·만료 경합 및 늦은 결제를 처리. 결제 기한은 선택 시 고정.
  4. 확정 후 채팅 권한·종료 시각·차단 상태를 메시지 저장 직전에 검사.
  5. 예약 상태 변경과 알림 대기 이벤트를 원자적으로 기록. 알림함 중복 방지·읽음 이력 관리. 인증·CS 답변 메일은 별도 절차.
  6. 운영 문의·증빙·반환 기록·접근 권한과 감사 로그. PG 반환은 운영자가 직접 처리하고 성공 확인 후 완료 기록.

메이트 신청 목록 정렬

B-29의 상태 우선순위, 최신 제출 시각, 재심사 수정본, 동률 및 페이지 처리 기준은 메이트 신청 목록 정렬 구현 계약을 따른다. pending → needs_info → approved/rejected(동순위), 각 그룹 submittedAt 내림차순·applicationId 오름차순이다. 시제품의 현재 표시 순서와 구분하여 구현·검증한다.

예약번호

표시용 예약번호는 RT- 접두사와 영문 대문자 A–Z·숫자 2–9로 구성한 6자리 코드다(예: RT-K7M3PX). 혼동하기 쉬운 숫자 0·1은 제외하며 DEMO·날짜 접두사는 붙이지 않는다. 여행자가 제안을 선택해 예약이 생성될 때 발급하고 확정·완료·취소 후에도 유지한다. 새 예약에는 새 번호를 발급하고 기존 번호는 재사용하지 않는다. 예약번호와 내부 예약 ID는 분리하며 기존 연결·URL·localStorage 키는 유지한다. 운영 목록·상세는 RT- 접두사를 붙여 표시한다. 예약 목록의 상세 보기는 record 쿼리로 독립 상세 페이지를 표시하며 목록과 검색 폼은 숨긴다. 목록으로 이동하면 기존 검색어·상태 필터를 유지한다. 존재하지 않는 예약은 안내와 목록 복귀 버튼을 표시한다. 검색은 접두사 포함·미포함 및 영문 대소문자와 관계없이 지원한다.

시제품은 각 예약 객체의 bookingNumber 필드와 기존 브라우저 상태의 bookingReferences에 접두사를 제외한 기존 6자리 코드를 저장하고 중복 시 다시 생성한다. 기존 예약·이력·요청별 예약·예시 예약의 누락 필드는 로드 및 저장 시 자동 보완하며 이미 발급한 번호는 유지한다. 예시·기존 예약에도 같은 규칙을 적용한다. 실제 서비스에서는 서버 난수 생성과 데이터베이스 UNIQUE 제약으로 동시 발급 중복을 방지하고 충돌 시 재시도한다. 예약번호는 접근 권한을 대신하지 않는다. 현재 서버 발급은 미연동이다.

MVP 예약 취소·수수료 전액 반환

예약 상세에서 금액 입력·반환 상태 수동 선택·부분 취소를 제공하지 않는다. 결제 전은 예약만 취소한다. 결제 후 여행자 취소와 운영 확인 예외(사고·질병·악천후)는 전액 반환 검토로 접수하고, 메이트 귀책은 반환 대상 아님으로 기록한다. 취소 사유와 실행 확인창을 필수로 제공한다. 취소된 유료 예약은 PG 전액 취소 확인·확인 번호·처리 사유를 받은 뒤 전액 환불 완료 기록을 저장한다. 반환 불가 예약은 예외 승인 확인과 근거가 필요하다. 반환액은 결제 수수료 전액으로 고정하고 중복 완료·부분 금액·권한 없는 요청은 거부한다. 여행비는 대상이 아니며 실제 PG 취소는 실행하지 않는다. 처리 이력과 기존 분쟁 기록은 유지한다.
