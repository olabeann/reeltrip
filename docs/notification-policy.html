수신자별 알림

카드에는 실제 목록처럼 2줄까지 표시합니다. 각 알림 아래에서 발송 시점과 수신 조건을 확인하세요. 문구는 한 벌만 사용합니다. 생략된 내용은 ‘문구 확인’에서 볼 수 있어요.

여행자·메이트 알림 12종. 선택·취소 등 본인이 한 행동과 단순 종료는 해당 화면에서 확인합니다. 서비스 알림은 알림함에 표시합니다. 현재 서버 알림·푸시는 미연결입니다.

새 제안·예약 변경은 즉시 알림함에 기록합니다. 채팅은 미읽음 표시만 사용합니다.

알림 문서 열기

제안·예약·취소·결제 기한 등 서비스 알림은 앱 안 알림함에 표시한다.

현재는 브라우저 시제품이다. 서버 사건 이력·예약 작업은 미연결이며 아래는 구현 기준이다. 앱·브라우저 푸시와 SMS도 미운영이다. 인증 메일과 사용자가 요청한 CS 답변 메일은 서비스 알림과 별개의 기존 업무 절차다.

1 알림을 만드는 기본 원칙

  • 서버에서 성공적으로 저장된 사건만 알림으로 기록한다. 실패한 클릭·요청으로 완료 알림을 만들지 않는다.
  • 여행자 선택만으로 예약이 확정되지 않는다. 메이트 수수료 10% 결제 성공 검증과 예약 확정 저장 후 확정 알림을 만든다. 여행비는 현장에서 현금으로 직접 지급한다.
  • 현재 모드와 관계없이 사건 당사자에게만 기록하며, 같은 계정·사건은 중복 기록하지 않는다.
  • 알림함 원문과 읽음 상태는 유지한다. 목록 방문 때마다 새 알림을 만들지 않는다.
  • 날짜·기한은 한국 시간으로 표시하고 서버에는 UTC로 저장한다.

문의 답변·자료 요청·반환 심사 상담운영팀의 개별 답변 이메일
운영팀 새 접수운영 웹 목록·Slack

기존 내부 저장 키는 호환성을 위해 보존한다.

3 사건별 기록 시점

각 메시지 카드의 ‘발송 시점’과 ‘수신·발송 조건’이 세부 기준이다. 여기서 서비스 알림의 ‘발송’은 알림함 기록을 뜻한다.

사건기록 시점과 대상
새 제안유효한 공개 요청에 제안 저장 성공 시 요청한 여행자에게 즉시 1회
메이트 선택선택과 결제 대기 예약 생성 성공 시 선택된 메이트에게 1회
예약 확정PG 성공 검증 후 확정 저장 시 양쪽에 각 1회. 결제 완료를 별도로 기록하지 않음
선택 해제거절 시 여행자에게, 결제 기한 만료 시 양쪽에 각 1회. 직접 거절한 메이트 제외
예약 취소확정 예약 취소 저장 시 상대방에게 1회. 운영팀 취소는 양쪽, 본인 취소는 제외
수수료 반환 완료실제 PG 반환 성공 확인 후 완료 저장 시 결제한 메이트에게 1회
등록 승인·신청 보완·반려심사 결과 저장 시 신청자에게 결과 버전별 1회. 재심사도 같은 문구
활동 제한운영팀의 제한 확정 시 해당 메이트에게 1회. 신고 접수만으로 생성하지 않음

본인 선택·거절·취소, 제안 철회·모집 종료, 여행 완료는 화면 상태로 확인한다. 별도 알림을 추가하지 않는다. 채팅은 읽지 않은 상태만 표시하고 메시지별 알림함 항목을 만들지 않는다.

4 예약 알림은 두 종류만 운영

알림생성 시점알림함 기록 시점대상·조건
결제 마감 안내메이트 선택 시고정 결제 기한 1시간 전선택이 유지되고 결제 대기인 메이트에게 1회
여행 전날 안내예약 확정 시첫날 여행 시작 24시간 전예약이 여전히 확정 상태인 양쪽에 각 1회

결제 기한은 메이트 선택 시각 + 24시간과 예약 첫날 시작 시각 중 빠른 시각으로 고정한다. 방문 시 연장하지 않는다. 선택 당시 기한까지 1시간 이하면 마감 안내를 생성하지 않는다. 확정 당시 여행 시작까지 24시간 이하면 지난 전날 안내를 생성하지 않는다. 여러 날 여행도 첫날 기준 1회다.

5 예약 작업

1분 주기 서버 작업은 결제 기한 만료와 예정된 알림함 기록만 처리한다. 브라우저가 닫혀 있어도 서버에서 처리해야 한다. 예정 시각 이하의 미처리 건을 조회하며 동시에 실행돼도 같은 작업은 한 번만 처리한다.

6 읽음 처리

알림을 누르면 읽음 처리 후 관련 상세 화면으로 이동한다. 읽은 알림도 남는다. 채팅은 해당 대화의 읽음 위치로 판단한다. 탭이 열려 있다는 이유만으로 읽음으로 보지 않는다. 읽지 않았다는 이유로 반복 알림을 만들지 않는다.

7 취소와 오래된 알림

  • 결제·거절·선택 해제·기한 만료 시 해당 마감 안내를 취소한다.
  • 예약 취소·완료 시 전날 안내를 취소한다. 탈퇴하거나 해당 기록의 소유·열람 권한을 잃으면 관련 새 알림 기록을 중단한다. 메이트 활동 제한은 계정 접근 권한 상실과 구분한다.
  • 예정 알림 기록 직전에 현재 상태·수신자·권한을 재확인한다.
  • 예정 시각보다 30분 넘게 지연된 리마인더는 폐기한다. 결제 기한·여행 시작 시각이 먼저 오면 그 시각에 폐기한다.
  • 과거 알림은 남기되 현재 상태로 연결한다. 취소된 예약의 결제·채팅을 다시 활성화하지 않는다.

활동이 제한된 메이트도 본인의 알림함·활동 제한 사유·문의 화면에는 접근할 수 있다. 제한 확정 알림을 정상 기록하고 읽을 수 있게 한다. 이 접근이 제안·결제·여행 진행 권한을 다시 부여하지는 않는다.

8 개발 구현 기준

항목확정 기준
수신자와 연결 대상각 알림에 수신자 ID·알림 종류·대상 유형·대상 ID를 저장한다. 예약·요청·신청 등 실제 사건의 대상을 지정하고 현재 선택된 예약이나 앱 모드로 추정하지 않는다. 상세 진입 시 서버에서 본인 권한을 확인한다. 대상이 삭제되거나 열람할 수 없으면 안내 후 목록으로 돌아간다.
결제와 기한 만료의 경합결제 검증과 만료 작업은 같은 선택·예약 버전에 대해 잠금 또는 조건부 갱신으로 상태를 한 번만 확정한다. 알림은 상태 확정과 함께 기록하며 실패한 갱신에서는 생성하지 않는다. 동일 경합에서 예약 확정·선택 해제 알림이 함께 만들어지지 않게 한다. PG 검증 결과와 이미 저장된 만료 상태가 불일치하면 자동으로 확정을 되살리지 않고 운영 확인으로 넘긴다.
발생 당시 문구 보존알림 생성 시 사건 발생 시각·치환된 제목/본문·사용한 변수 값·문구 버전·언어를 함께 저장한다. 날짜·금액·템플릿이 나중에 바뀌어도 과거 알림을 다시 치환하지 않는다. 클릭한 상세 화면은 현재 상태를 보여준다.
활동 제한 계정의 접근활동 권한과 본인 알림 열람 권한을 분리한다. 활동 제한 중에도 본인 알림함·제한 사유·문의는 제공한다. 다른 사용자의 기록은 볼 수 없다.
양쪽 수신자의 공통 문구여행자·메이트가 함께 받는 문구는 역할에 치우치지 않게 작성한다. 선택 해제 제목은 ‘예약이 성사되지 않았어요’로 통일한다.

사건 저장과 알림 기록을 같은 서버 트랜잭션으로 처리하거나 동일 사건 키로 복구한다. 사건 ID·수신자·알림 종류를 중복 키로 사용한다. 예약 작업은 예약 ID·선택 또는 예약 버전·종류·수신자로 중복을 막는다. 저장 오류를 복구할 때도 새 알림을 중복 생성하지 않는다.

9 서비스 알림과 별개인 업무

인증 링크와 만료 시각은 인증 시스템이 제공한다. CS 답변 이메일에는 운영자가 작성한 실제 답변·요청 자료·심사 사유·회신 방법을 포함한다. 반환 완료·활동 제한 알림 자체는 알림함에만 기록하고, 사용자가 문의한 경우에만 CS 절차로 답변한다.

새 문의·신고·노쇼·반환 요청은 운영 웹과 Slack에 접수당 1회 표시한다. Slack에는 접수 번호·유형·보호된 운영 상세 링크만 포함한다. 사용자 연락처·문의 본문·첨부 파일을 넣지 않는다.

10 MVP 제외 항목

앱·브라우저 푸시, SMS, 광고 캠페인, 반복 독촉, 후기 요청, 전체 메이트 추천 발송은 제외한다. 별도 조용한 시간·세부 유형별 설정도 추가하지 않는다.

12 문구는 하나만 관리한다

  • 알림 종류마다 제목·본문 한 벌을 확정한다. 전체용·짧은용·향후 푸시용 문구를 따로 만들지 않는다. 제목은 상태 변화, 본문은 필요한 행동과 예약 식별 정보를 간결하게 적는다.
