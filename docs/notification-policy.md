# 릴트립 알림 운영 정책

작성일: 2026-11-24

[알림 문서 열기](notification-policy.html)

**제안·예약·취소·결제 기한 등 서비스 알림은 앱 안 알림함에 표시한다.**

현재는 브라우저 시제품이다. 서버 사건 이력·예약 작업은 미연결이며 아래는 구현 기준이다. 앱·브라우저 푸시와 SMS도 미운영이다. 인증 메일과 사용자가 요청한 CS 답변 메일은 서비스 알림과 별개의 기존 업무 절차다.

## 1 알림을 만드는 기본 원칙

- 서버에서 성공적으로 저장된 사건만 알림으로 기록한다. 실패한 클릭·요청으로 완료 알림을 만들지 않는다.
- 여행자 선택만으로 예약이 확정되지 않는다. 메이트 수수료 10% 결제 성공 검증과 예약 확정 저장 후 확정 알림을 만든다. 여행비는 현장에서 현금으로 직접 지급한다.
- 현재 모드와 관계없이 사건 당사자에게만 기록하며, 같은 계정·사건은 중복 기록하지 않는다.
- 알림함 원문과 읽음 상태는 유지한다. 목록 방문 때마다 새 알림을 만들지 않는다.
- 날짜·기한은 한국 시간으로 표시하고 서버에는 UTC로 저장한다.

## 2 채널 구분

| 구분 | 제공 방식 |
|---|---|
| 서비스 알림 12종 | 알림함과 관련 상세 화면 |
| 채팅 | 채팅방·목록의 미읽음 표시 |
| 문의 답변·자료 요청·반환 심사 상담 | 운영팀의 개별 답변 이메일 |
| 운영팀 새 접수 | 운영 웹 목록·Slack |

기존 내부 저장 키는 호환성을 위해 보존한다.

## 3 사건별 기록 시점

각 메시지 카드의 ‘발송 시점’과 ‘수신·발송 조건’이 세부 기준이다. 여기서 서비스 알림의 ‘발송’은 알림함 기록을 뜻한다.

| 사건 | 기록 시점과 대상 |
|---|---|
| 새 제안 | 유효한 공개 요청에 제안 저장 성공 시 요청한 여행자에게 즉시 1회 |
| 메이트 선택 | 선택과 결제 대기 예약 생성 성공 시 선택된 메이트에게 1회 |
| 예약 확정 | PG 성공 검증 후 확정 저장 시 양쪽에 각 1회. 결제 완료를 별도로 기록하지 않음 |
| 선택 해제 | 거절 시 여행자에게, 결제 기한 만료 시 양쪽에 각 1회. 직접 거절한 메이트 제외 |
| 예약 취소 | 확정 예약 취소 저장 시 상대방에게 1회. 운영팀 취소는 양쪽, 본인 취소는 제외 |
| 수수료 반환 완료 | 실제 PG 반환 성공 확인 후 완료 저장 시 결제한 메이트에게 1회 |
| 등록 승인·신청 보완·반려 | 심사 결과 저장 시 신청자에게 결과 버전별 1회. 재심사도 같은 문구 |
| 활동 제한 | 운영팀의 제한 확정 시 해당 메이트에게 1회. 신고 접수만으로 생성하지 않음 |

본인 선택·거절·취소, 제안 철회·모집 종료, 여행 완료는 화면 상태로 확인한다. 별도 알림을 추가하지 않는다. 채팅은 읽지 않은 상태만 표시하고 메시지별 알림함 항목을 만들지 않는다.

## 4 예약 알림은 두 종류만 운영

| 알림 | 생성 시점 | 알림함 기록 시점 | 대상·조건 |
|---|---|---|---|
| 결제 마감 안내 | 메이트 선택 시 | 고정 결제 기한 1시간 전 | 선택이 유지되고 결제 대기인 메이트에게 1회 |
| 여행 전날 안내 | 예약 확정 시 | 첫날 여행 시작 24시간 전 | 예약이 여전히 확정 상태인 양쪽에 각 1회 |

결제 기한은 메이트 선택 시각 + 24시간과 예약 첫날 시작 시각 중 빠른 시각으로 고정한다. 방문 시 연장하지 않는다. 선택 당시 기한까지 1시간 이하면 마감 안내를 생성하지 않는다. 확정 당시 여행 시작까지 24시간 이하면 지난 전날 안내를 생성하지 않는다. 여러 날 여행도 첫날 기준 1회다.

## 5 예약 작업

1분 주기 서버 작업은 결제 기한 만료와 예정된 알림함 기록만 처리한다. 브라우저가 닫혀 있어도 서버에서 처리해야 한다. 예정 시각 이하의 미처리 건을 조회하며 동시에 실행돼도 같은 작업은 한 번만 처리한다.

## 6 읽음 처리

알림을 누르면 읽음 처리 후 관련 상세 화면으로 이동한다. 읽은 알림도 남는다. 채팅은 해당 대화의 읽음 위치로 판단한다. 탭이 열려 있다는 이유만으로 읽음으로 보지 않는다. 읽지 않았다는 이유로 반복 알림을 만들지 않는다.

## 7 취소와 오래된 알림

- 결제·거절·선택 해제·기한 만료 시 해당 마감 안내를 취소한다.
- 예약 취소·완료 시 전날 안내를 취소한다. 탈퇴하거나 해당 기록의 소유·열람 권한을 잃으면 관련 새 알림 기록을 중단한다. 메이트 활동 제한은 계정 접근 권한 상실과 구분한다.
- 예정 알림 기록 직전에 현재 상태·수신자·권한을 재확인한다.
- 예정 시각보다 30분 넘게 지연된 리마인더는 폐기한다. 결제 기한·여행 시작 시각이 먼저 오면 그 시각에 폐기한다.
- 과거 알림은 남기되 현재 상태로 연결한다. 취소된 예약의 결제·채팅을 다시 활성화하지 않는다.

활동이 제한된 메이트도 본인의 알림함·활동 제한 사유·문의 화면에는 접근할 수 있다. 제한 확정 알림을 정상 기록하고 읽을 수 있게 한다. 이 접근이 제안·결제·여행 진행 권한을 다시 부여하지는 않는다.

## 8 개발 구현 기준

| 항목 | 확정 기준 |
|---|---|
| 수신자와 연결 대상 | 각 알림에 수신자 ID·알림 종류·대상 유형·대상 ID를 저장한다. 예약·요청·신청 등 실제 사건의 대상을 지정하고 현재 선택된 예약이나 앱 모드로 추정하지 않는다. 상세 진입 시 서버에서 본인 권한을 확인한다. 대상이 삭제되거나 열람할 수 없으면 안내 후 목록으로 돌아간다. |
| 결제와 기한 만료의 경합 | 결제 검증과 만료 작업은 같은 선택·예약 버전에 대해 잠금 또는 조건부 갱신으로 상태를 한 번만 확정한다. 알림은 상태 확정과 함께 기록하며 실패한 갱신에서는 생성하지 않는다. 동일 경합에서 예약 확정·선택 해제 알림이 함께 만들어지지 않게 한다. PG 검증 결과와 이미 저장된 만료 상태가 불일치하면 자동으로 확정을 되살리지 않고 운영 확인으로 넘긴다. |
| 발생 당시 문구 보존 | 알림 생성 시 사건 발생 시각·치환된 제목/본문·사용한 변수 값·문구 버전·언어를 함께 저장한다. 날짜·금액·템플릿이 나중에 바뀌어도 과거 알림을 다시 치환하지 않는다. 클릭한 상세 화면은 현재 상태를 보여준다. |
| 활동 제한 계정의 접근 | 활동 권한과 본인 알림 열람 권한을 분리한다. 활동 제한 중에도 본인 알림함·제한 사유·문의는 제공한다. 다른 사용자의 기록은 볼 수 없다. |
| 양쪽 수신자의 공통 문구 | 여행자·메이트가 함께 받는 문구는 역할에 치우치지 않게 작성한다. 선택 해제 제목은 ‘예약이 성사되지 않았어요’로 통일한다. |


사건 저장과 알림 기록을 같은 서버 트랜잭션으로 처리하거나 동일 사건 키로 복구한다. 사건 ID·수신자·알림 종류를 중복 키로 사용한다. 예약 작업은 예약 ID·선택 또는 예약 버전·종류·수신자로 중복을 막는다. 저장 오류를 복구할 때도 새 알림을 중복 생성하지 않는다.

## 9 서비스 알림과 별개인 업무

인증 링크와 만료 시각은 인증 시스템이 제공한다. CS 답변 이메일에는 운영자가 작성한 실제 답변·요청 자료·심사 사유·회신 방법을 포함한다. 반환 완료·활동 제한 알림 자체는 알림함에만 기록하고, 사용자가 문의한 경우에만 CS 절차로 답변한다.

새 문의·신고·노쇼·반환 요청은 운영 웹과 Slack에 접수당 1회 표시한다. Slack에는 접수 번호·유형·보호된 운영 상세 링크만 포함한다. 사용자 연락처·문의 본문·첨부 파일을 넣지 않는다.

## 10 MVP 제외 항목

앱·브라우저 푸시, SMS, 광고 캠페인, 반복 독촉, 후기 요청, 전체 메이트 추천 발송은 제외한다. 별도 조용한 시간·세부 유형별 설정도 추가하지 않는다.

## 11 검수 기준

| 상황 | 기대 결과 |
|---|---|
| 새 제안 저장 | 여행자 알림함에 즉시 1건 |
| 같은 PG 웹훅 3회 | 예약 확정 1회, 양쪽 알림함 각 1건 |
| 채팅을 읽지 않음 | 채팅 미읽음 표시만 유지 |
| 이메일 주소가 없는 계정 | 서비스 알림함 정상 제공 |
| 결제 마감 직전 결제 성공 | 마감 안내 취소, 확정 알림만 기록 |
| 선택 시 기한이 40분 뒤 | 선택 알림만 기록, 1시간 전 안내 없음 |
| 여행 20시간 전 확정 | 확정 알림만 기록, 전날 안내 없음 |
| 서버 중복 실행 | 같은 알림 중복 기록 없음 |
| 결제 성공 검증과 기한 만료가 동시에 실행 | 같은 선택 버전에서 하나의 상태 전이만 성공하고 해당 결과의 알림만 생성 |
| 만료 후 PG 성공 결과가 뒤늦게 확인됨 | 자동 예약 복원·확정 알림 없이 운영 확인 |
| 같은 날짜의 다른 예약 알림 열기 | 알림에 저장된 대상 ID의 예약으로 연결 |
| 알림 생성 후 날짜·금액·문구 수정 | 기존 알림 문구는 보존하고 상세는 현재 상태로 표시 |
| 메이트 활동 제한 후 알림 열기 | 본인 알림·제한 사유·문의 접근 가능, 활동 권한은 제한 유지 |
| 취소 후 과거 확정 알림 열기 | 현재 취소 상태로 연결 |
| 문의 답변 발송 | 실제 답변 이메일 1건만 제공 |

## 12 문구는 하나만 관리한다

- 알림 종류마다 제목·본문 한 벌을 확정한다. 전체용·짧은용·향후 푸시용 문구를 따로 만들지 않는다. 제목은 상태 변화, 본문은 필요한 행동과 예약 식별 정보를 간결하게 적는다.
- 제목 25자·본문 80자 이내를 작성 목표로 삼되, 날짜·금액 등 필수 정보를 잘라 맞추지 않는다. 변수 치환 후 검수하고 긴 사유·개인정보는 관련 상세 또는 개별 이메일 본문에 둔다. 별도 자동 요약이나 길이 초과 발송 차단 기능은 MVP에 추가하지 않는다.
- 알림함 목록은 제목·본문 각각 최대 2줄, 초과 부분은 …으로 표시한다. 저장한 문구는 보존한다. 문서의 ‘문구 확인’에서 생략 없는 동일 문구를 볼 수 있다.
- 인증 메일과 사용자가 요청한 CS 답변 메일은 별도 업무 절차로 유지한다.
- 앱·브라우저 푸시는 MVP 미운영이다. OS별 페이로드·펼침 설계는 도입 시 다루며 현재 문구 문서에 별도 푸시 미리보기를 만들지 않는다.
- 여행일과 알림 발생 날짜는 YYYY-MM-DD, 여행 날짜 범위는 YYYY-MM-DD ~ YYYY-MM-DD로 통일한다. 결제기한은 YYYY-MM-DD HH:mm (한국 시간)으로 표시하며 시간은 24시간제를 사용한다. 실제 저장값은 바꾸지 않는다. 긴 값은 화면에서만 말줄임한다.

변수명은 문서용 치환 키이며 실제 DB 필드명은 구현 시 매핑한다. 원문 템플릿은 한 벌로 유지하고 아래 값만 치환한다. 예시 값을 운영 기본값으로 사용하지 않는다. 필수 값이 없으면 빈 문자열이나 중괄호를 그대로 발송하지 않고 데이터 오류로 확인한다. 사용자 입력은 텍스트로 이스케이프하며, 표시 날짜는 한국 시간 기준이다.

| 변수 | 치환할 값과 표시 형식 | 예시 |
|---|---|---|
| {여행일} | 해당 요청·예약에 저장된 여행 날짜. 하루는 YYYY-MM-DD, 여러 날은 시작일 ~ 종료일로 표시 | 2026-12-01 또는 2026-12-01 ~ 2026-12-03 |
