# 릴트립 알림 종류와 발송 정책

작성일: 2026-11-24

여행자·메이트·운영팀에 필요한 알림 종류, 발송 시점, 이동 화면과 사용자 설정을 정리한다. 알림은 사용자가 해야 할 일과 예약·여행에 영향을 주는 변화를 중심으로 구성한다.

이 문서는 이전 채팅 「알림 종류와 발송 조건 정리」의 설계안을 저장하고 현재 서비스 흐름에 맞춰 보완한 초안이다. 아래 발송 주기와 설정 기본값은 제안이며 실제 푸시·서버 발송 구현 완료를 뜻하지 않는다.

## 홈페이지 MVP 적용 범위

가입 방법 선택 화면에는 동의 체크박스를 표시하지 않는다. 이메일 가입 화면에서만 이메일 입력란 아래, 인증번호 받기 버튼 위에 `[선택] 이벤트·혜택 등 광고성 이메일 수신 동의`를 기본 미선택으로 제공한다. 별도 안내 문구 없이 선택 동의 체크박스만 표시하며, 미동의 상태에서도 가입할 수 있다. 인증 성공 시 선택을 저장한다. 소셜 신규 가입은 별도 동의 단계 없이 광고 수신 OFF로 저장하며, 이메일 가입 중 선택했던 값도 이어받지 않는다. 이메일·소셜 로그인은 기존 동의를 변경하지 않는다. 가입 후 마이 → 설정 → 알림 설정에서 동의하거나 철회할 수 있다.

마이 → 설정 → 알림 설정에서 다음 두 항목을 저장한다. 고객과 메이트는 같은 설정을 사용한다.

| 설정 | 기본값 | 범위 |
|---|---|---|
| 제안·예약·채팅 소식 이메일 받기 | 켜짐 | 이용 중인 여행에 관한 서비스 이메일 |
| 이벤트·혜택 등 광고성 이메일 수신 동의 | 꺼짐 | 가입 시 선택과 연결되며 언제든 철회 가능 |

이메일 설정을 꺼도 홈페이지 알림함은 유지한다. 인증 메일은 이 설정과 별개다. MVP에서는 브라우저 푸시 권한, SMS, 야간 광고 동의, 조용한 시간, 대화방별 음소거와 세부 유형별 스위치를 제공하지 않는다. 광고 이메일은 야간에 발송하지 않는 운영 기준으로 한다.

현재 구현은 브라우저 저장 시연이다. 한국어·영어 홈페이지가 `reeltrip-notification-preferences-v1`을 공유하고 탈퇴 시 삭제한다. 서비스 이메일 여부, 광고 수신 여부, 변경 시각, 변경 위치, 이메일 채널과 정책 버전을 저장한다. 저장 실패 시 완료로 표시하지 않는다. 실제 이메일 발송이나 OS 권한 요청은 수행하지 않는다.

실서비스 연결 시 로그인 계정별 서버 설정과 동의·철회 이력을 저장하고, 발송 직전에 최신 설정을 확인해야 한다. 소셜 가입자의 이메일은 실제 제공·검증된 주소만 사용한다. 운영 문의 답변·인증 같은 개별 요청 응답과 광고를 혼합하지 않는다.

아래 상세 알림 유형과 발송 주기는 확장 검토용이다. 현재 홈페이지 MVP 범위와 충돌하면 이 절을 우선한다.

## 서비스 기준과 현재 구현

- 고객·메이트 통합 앱을 사용하고 운영 웹은 별도로 둔다.
- 공개 여행 → 복수 제안 → 여행자 선택 → 메이트의 수수료 10% 결제 → 예약 확정 순서다. 메이트 선택과 예약 확정을 구분한다.
- 여행비는 여행자가 메이트에게 현장 현금으로 직접 지급한다.
- 현재 앱은 예약·요청 상태를 바탕으로 알림 목록을 만들고 브라우저에 읽음 상태를 저장한다. 종류별 탭, 실제 푸시, 서버 발송 이력 및 시간별 리마인더가 구현된 상태는 아니다.
- 현재 시제품의 제안 유효기간은 24시간이다. 수수료 결제 기한은 저장된 기한을 우선 사용하고, 없으면 요청 시각부터 24시간과 여행 시작 시각 중 빠른 시각을 사용한다. 실서비스에서도 서버가 확정한 기한을 기준으로 리마인더를 예약한다.

## 여행자 알림

| 종류 | 발송 시점과 조건 | 눌렀을 때 이동 |
|---|---|---|
| 새로운 제안 도착 | 공개 여행에 메이트 제안 등록 시 | 해당 여행의 제안 목록 |
| 제안 마감 임박 | 유효한 제안 만료 2시간 전, 아직 선택하지 않았다면 여행별 1회 | 제안 확인·선택 |
| 메이트 확정 대기 | 여행자가 제안을 선택한 직후, 화면과 알림함으로 안내 | 예약 진행 상태 |
| 예약 확정 | 메이트의 10% 수수료 결제가 서버에서 검증되면 즉시 | 확정 예약 상세 |
| 매칭 불발과 재모집 | 선택된 메이트의 거절 또는 결제 기한 만료 시 | 여행 시작 전이면 다시 열린 모집과 유효한 제안 목록, 시작 후면 일정 변경 안내 |
| 새로운 채팅 | 확정 예약의 상대 메시지 도착 시, 해당 대화를 보고 있지 않을 때 | 해당 채팅방 |
| 중요 일정 변경 | 만남 시간·장소 등 변경 요청 또는 합의 시 | 변경 내용 확인 |
| 예약 취소 | 취소가 처리되면 즉시 | 취소 결과와 후속 안내 |
| 여행 준비 | 확정 여행 시작 24시간 전 | 시간·만남 장소·준비사항 |
| 곧 만나요 | 확정 여행 시작 2시간 전 | 만남 장소·메이트 연락 |
| 후기 요청 | 여행 완료 처리 2시간 후, 미작성인 경우 1회 | 후기 작성 |
| 문의 답변 | 운영자가 문의에 답변하면 | 해당 문의 |

여행 준비 안내에는 약속한 여행비와 현장 현금 직접 지급 방식을 명시한다. 여행비를 플랫폼에서 결제한 것으로 오해하게 하는 표현을 쓰지 않는다. 확정 후 날짜·인원 변경은 현재 정책에 따라 취소 후 새 요청으로 처리하며, 별도 일정 변경 기능이 있는 것으로 표시하지 않는다.

직접 요청을 철회하거나 확정 예약을 취소한 경우에는 자동으로 재모집하지 않는다. 취소 결과와 수수료 환불 결과는 별도의 사건으로 안내한다.

## 메이트 알림

| 종류 | 발송 시점과 조건 | 눌렀을 때 이동 |
|---|---|---|
| 조건에 맞는 새 공개 여행 | 활동 지역·언어·가능 일정이 맞는 요청 등록 시, 기본 30분 단위 묶음 | 공개 여행 상세 |
| 내 제안이 선택됨 | 여행자가 본인 제안을 선택하면 즉시 | 수수료 금액·결제 기한·결제 화면 |
| 수수료 결제 마감 임박 | 결제 기한 1시간 전, 미결제인 경우 1회 | 수수료 결제 |
| 결제 실패 | 실제 실패가 확인되면, 결제 화면에서는 화면 안내 우선 | 재시도 화면 |
| 결제 완료와 예약 확정 | 서버에서 결제 성공이 검증되면 하나의 알림으로 발송 | 확정 예약·수수료 결제 내역 |
| 선택 철회 또는 매칭 만료 | 선택이 해제되거나 결제 기한이 종료되면 | 종료 사유와 현재 상태 |
| 제안한 여행 모집 종료 | 다른 메이트 확정 또는 공개 요청 철회 시, 알림함에 표시 | 보낸 제안 결과 |
| 채팅·중요 일정 변경·취소 | 본인 관련 확정 예약에서 발생하면 | 해당 대화·예약 |
| 여행 준비·만남 임박 | 확정 여행 시작 24시간 전·2시간 전 | 일정·만남 장소·연락 |
| 메이트 심사 결과 | 승인·보완 요청·활동 제한 결정 시 | 결과와 필요한 조치 |
| 수수료 환불 결과 | 실제 환불 처리 결과 확인 시 | 수수료 환불 내역 |

새 공개 여행은 조건에 맞는 메이트에게만 보낸다. 결제 기한까지 남은 시간이 리마인더 기준보다 짧으면 이미 지난 알림을 뒤늦게 발송하지 않고, 선택 알림에 실제 남은 기한을 표시한다.

## 발송 방식과 중복 방지

| 상황 | 권장 방식 |
|---|---|
| 예약 확정·제안 선택됨·취소·중요 변경 | 즉시 푸시와 알림함 |
| 제안 도착·새 채팅 | 푸시와 관련 화면의 읽지 않음 표시 |
| 여행 준비·마감 임박 | 예약된 시각에 푸시와 알림함 |
| 새 공개 여행·후기 요청 | 사용자 설정에 따라 묶음 또는 일반 푸시 |
| 본인이 방금 수행한 저장·제출·선택 | 화면에서 결과를 표시하고 동일 내용 푸시는 생략 |
| 현재 보고 있는 채팅방의 메시지 | 대화에 바로 표시하고 푸시·소리는 생략 |

- 제안은 첫 도착 시 즉시 알리고, 이후 5분 내 도착분은 “새 제안 3개”처럼 묶는다.
- 같은 대화의 연속 메시지는 기존 푸시를 갱신하고 소리 반복을 제한한다.
- 결제·선택·취소·후기 작성이 완료되면 관련 예약 발송을 취소한다.
- 일정이 바뀌면 기존 여행 준비 알림을 취소하고 변경된 시각으로 다시 예약한다.
- 오래된 알림을 눌러도 현재 상태를 확인하여 끝난 결제나 선택을 다시 요구하지 않는다.
- 휴대폰의 알림 권한, 무음과 집중 모드를 따른다.
- 고객·메이트 중 현재 모드와 관계없이 본인에게 필요한 알림을 수신하고, 탭하면 해당 역할의 허용된 화면으로 연결한다.
- 서버 이벤트별 중복 방지 식별자를 사용해 재시도나 결제 웹훅 중복 수신으로 같은 알림을 반복 생성하지 않는다.

## 알림 설정

진입 위치는 `마이 → 설정 → 알림 설정`으로 제안한다.

| 항목 | 기본값 제안 |
|---|---|
| 예약·결제·취소·중요 변경 푸시 | 켜짐 |
| 새로운 제안 | 켜짐 |
| 채팅 | 켜짐, 대화방별 음소거 제공 |
| 여행 준비·만남 알림 | 켜짐 |
| 조건에 맞는 공개 여행 | 메이트용, 켜짐·30분 묶음, 지역·요일 조건 설정 |
| 후기 요청 | 켜짐 |
| 이벤트·혜택 | 꺼짐, 별도 동의 |
| 조용한 시간 | 사용자 현지 시간 22:00~08:00 |
| 조용한 시간 중 진행 중 여행의 중요 알림 허용 | 사용자가 별도 선택 |
| 잠금화면 메시지 내용 미리보기 | 꺼짐 |

중요 거래 내역은 푸시를 꺼도 알림함에서 확인할 수 있다. 조용한 시간에 미룬 알림은 종료 후 아직 유효한 내용만 묶어 보낸다. 여행 시각은 여행지 시간대로 계산하고 한국 여행을 안내할 때 해외 사용자에게 한국 시간 기준임을 명시한다.

## 운영팀 알림

운영 웹에 메이트 심사·보완 제출, 취소·분쟁·신고, 문의 접수, 결제 확인 오류·환불 실패를 모은다. 일반 문의는 업무 목록으로 관리한다. 여행 직전 취소, 노쇼 신고, 결제 상태 불일치처럼 빠른 대응이 필요한 사건은 즉시 운영 알림으로 보낸다.

각 사건에 담당자와 처리 상태를 기록해 중복 대응을 줄인다. 앱 사용자 알림과 운영팀 내부 알림의 수신 범위를 분리한다.

## 구현 우선순위와 기록 항목

우선 범위는 제안 도착 → 메이트 선택 → 수수료 결제 → 예약 확정 → 채팅 → 여행 전 안내 → 취소·변경이다. 현재 상태에서 알림 문구를 만드는 방식에서 실제 이벤트 이력을 저장하는 방식으로 확장한다.

| 기록 항목 | 용도 |
|---|---|
| 이벤트 식별자와 유형 | 사건 구분과 중복 방지 |
| 발생 시각과 예약 발송 시각 | 정렬·리마인더 실행 |
| 수신자와 대상 역할 | 고객·메이트·운영팀 전달 범위 |
| 관련 여행·제안·예약·채팅 식별자 | 올바른 상세 화면 연결 |
| 읽음 상태와 읽은 시각 | 읽지 않은 알림 표시 |
| 발송 채널·결과·재시도 상태 | 실패 추적과 재발송 |
| 만료 또는 취소 사유 | 더 이상 유효하지 않은 알림 발송 방지 |

실서비스 적용 전에는 발송 주기, 조용한 시간 기본값, 이력 보관 기간, 재시도 횟수와 오류 대응 기준을 확정한다. 후기·일정 변경 등 알림이 연결될 기능은 실제 제공 범위에 맞춰 활성화한다.
