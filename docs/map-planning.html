이번 기획의 출발점

개발자는 쇼츠·릴스 링크에서 장소를 추출하고 Google 지도에 핀을 표시하는 기술의 구현 가능성을 확인했다는 사용자 설명을 전제로 한다. 영상 속 장소를 다시 검색하는 수고, 한국 지리와 이동시간을 모르는 불편, 방문일을 결정하기 어려운 문제를 지도와 날짜별 일정으로 해결한다. API의 실제 성능·한국 이동수단별 경로 지원·평점·리뷰·영상 타임스탬프 제공까지 확인된 것으로 확대 해석하지 않는다.

이전 설계과 릴트립

항목이전 설계 · 자유여행 계획 앱릴트립 · 가이드 여행 앱
공통 시작공개 링크 입력 → 분석 상태 → 지도 핀·사진·장소 목록 → 지점 확인 → 날짜별 일정
마지막 행동여행 저장 → 이날 공유 → 실제 지도에서 장소 확인 → 직접 여행날짜 선택 → 이날 가이드 요청 → 가이드 동선 검토 → 변경 사항·총액 확인 → 예약
이용자 가치영상에 저장한 곳을 한글 이름을 몰라도 찾아 자신의 속도로 여행같은 장소·일정에 영어 안내와 주문·이동 도움 추가
운영 전제정보·일정 도구. 매칭·여행 예약·동행 판매 제외기존 사업 등록·가이드 자격·계약·보험 등 출시 게이트 유지. 지도 기능만으로 충족되지 않음

모바일 IA·화면 구조

발견(링크 입력 → 처리 → 지도 결과) → 내 장소(선택한 날) → 내 여행(날짜 탭 + 지도 + 일정 목록 + 저장·공유). 릴트립은 가이드 탭과 요청·견적·예약이 추가된다. 기존 A-01~14, B-01~30 화면 ID를 유지하고 A/B-03,06을 중심으로 개정한다.

  1. 지도 결과: 원본 영상 → 사진 핀 지도 → 선택 카드 → 전체·카페·쇼핑·맛집·공원 → 지점 확인 → 일정 짜기.
  2. 일정: 영상 추가 → 1일차·2일차·날짜 추가 → 해당 날짜 번호 핀 → 아래 일정 시트 → 시작 시간·장소 순서·체류·다른 날로 이동 → 저장.
  3. 릴트립 요청: 현재 날짜와 장소 순서·필수 장소·언어·인원·도움 요청을 전달. 전체 여행이 예약되는 것으로 보이지 않게 하루 단위 표시.

기능과 정책

기능동작·예외
지도·목록 동기화사진 핀 선택 시 같은 장소 카드 강조. 순서 변경 시 핀 번호 변경. 정확한 좌표 없는 후보는 지도 밖 확인 필요 목록. 미제공 평점·리뷰 수·영상 시각은 표시하지 않음.
날짜별 편집1개 여행 최대 7일, 하루 20곳. 날짜·시작 시간·순서·체류 보존. 다른 날 이동은 원래 날에서 제거하고 대상 날 끝에 추가. 같은 날 중복 추가는 병합. 다른 날 재방문은 가능.
경로와 시간핀 연결만으로 최적 경로나 실제 이동시간을 약속하지 않음. 실제 경로 응답이 있을 때만 이동수단·구간별 소요시간·조회 시각 표시. 경로 실패 시 장소 순서는 유지하고 이동시간 미확인으로 표시. 휴무·대기·예약 필요는 확인 근거가 있을 때만 안내.
추출·중복부분 성공 장소 유지. 후보가 없으면 다른 링크·직접 추가. 같은 Google place_id만 병합하고 여러 원본 영상 출처 보존. 이번 시제품은 고정 4곳을 반환하며 실제 중복 추출·출처 병합은 API 인수 검증 대상.
저장·공유모든 날짜를 브라우저에 저장. 공유는 선택한 하루만 텍스트·JSON으로 제공. 로컬 저장 실패 안내. 출시 버전 계정 동기화·공유 링크는 별도 구현.
가이드 요청현재 하루만 독립 스냅샷. 성수·최대 6곳·4시간·1~4명·48시간 이후라는 기존 파일럿 기준 유지. 동선은 가이드가 검토하고 변경에 고객 동의를 받음. 실제 이동시간 검증 전 자동으로 진행 가능 판정하지 않음.

기획과 실제 구현 상태

구현한 시제품: 링크 형식 검사, 예시 분석, 사진 핀 선택, 지도 우선 결과, 날짜 추가·전환, 순서·체류 편집, 날짜 간 이동, 저장·복원, 하루 공유, 릴트립 하루 요청. Google 장소 검색 링크는 외부 Google Maps로 연결된다.

개발자 연동 필요: 실제 링크 분석 API, Google Maps SDK의 실제 지도·마커, Places의 정확한 지점·좌표, 이동수단별 경로·시간, 로그인·서버 저장. 지도는 Google 화면처럼 오인시키지 않도록 시연 지도로 표시한다. API 키나 기존 개발 결과물을 전달받지 않았으므로 실연동 완료로 보고하지 않는다.

개발 전달 계약 · 제안

  • POST /extractions: source_url, request_id → job_id. 상태 pending / processing / partial / succeeded / failed. 재시도는 동일 request_id에 중복 작업 방지.
  • GET /extractions/{id}: candidates[{candidate_id, provider_place_id, name_local, name_display, formatted_address, lat, lng, category, photos_with_attribution, sources[{url,timestamp_seconds?}], verification_status}]. 없는 정보는 null. 좌표·식별자 없는 후보를 확정 핀으로 표시하지 않는다.
  • Trip: id, timezone=Asia/Seoul, title, version, days[{day_id,date,start_time,stops[{stop_id,place_id,order,dwell_minutes,must_visit}]}]. 같은 장소라도 날짜별 체류시간은 별도 보관.
  • Route: day_id, ordered_place_ids, travel_mode → legs[{from,to,duration_seconds,distance_meters,status}], geometry, checked_at. 응답이 오래되었거나 실패하면 화면에 불확실성 표시. 장소 순서 변경 시 이전 응답 폐기.
  • GuideRequest: immutable day snapshot + route status + language + party + notes. 제출 후 여행 편집은 요청·견적·예약 사본을 덮어쓰지 않는다.
  • 클라이언트 지도 키는 앱·도메인 및 API 제한 적용. 추출 서버 URL 허용 목록·리디렉션 검사. 지도 데이터·사진 표시 및 저장은 제공자 조건을 확인한다.

인수 테스트

  1. 실제 공개 링크 10개: 올바른 장소·지점·원본 출처를 표본 대조. 비공개·삭제·잘못된 링크·0개·부분 성공 포함.
  2. 핀↔카드 선택, 1→3 순서 변경, 날짜 이동, 새로고침 후 날짜별 복원 확인.
  3. 동일 지점 재추출은 중복 없이 출처 병합. 동명이점은 병합하지 않음.
  4. 한국 내 도보·대중교통 지원 구간에서 경로·시간 실제 응답 확인. 실패·오프라인 시 일정 보존.
  5. 2일차 요청에 1일차가 포함되지 않으며 요청 후 원본 편집이 견적에 전파되지 않음. 이전 설계에는 요청·결제 UI 없음.
