운영 정책

합의한 MVP 운영 정책 · 2026-11-24

현재 릴트립 단일 서비스의 운영 기준이다. 고객/메이트 통합 앱, 운영팀 별도 웹. 아래 정책은 이 문서 내 이전 설명과 충돌할 때 우선한다. 실제 인증·결제·메일·Slack·서버 동기화가 연결된 출시 완료본을 의미하지 않는다.

요청·제안·예약

  • 여행자는 같은 날짜에 진행 중인 요청·예약 1건만 허용한다. 날짜가 겹치지 않으면 여러 요청을 진행할 수 있다. 여러 날 여행은 해당 기간에 적용한다. 한 요청에는 복수 메이트 제안을 받는다.
  • 메이트는 시간대와 관계없이 하루 확정 예약 1건이다. 여행자가 먼저 선택한 예약의 수수료 결제 대기 중에도 날짜를 확보한다. 확보된 날짜와 겹치는 요청은 메이트에게 숨기고 기존 제안은 선택 불가로 처리한다. 기한 만료·진행 거절로 해제되면 아직 유효한 제안의 선택과 새로운 제안이 다시 가능하다.
  • 여행자 선택 전 메이트 제안 철회 가능. 선택 후에는 진행 거절·취소 규칙을 적용한다. 유효한 제안 수정·중복 발행 제한은 유지한다.
  • 선택 후 24시간과 예약 첫날 시작 시각 중 먼저 오는 때까지 10% 수수료를 결제한다. 만료·진행 거절 시 선택 해제, 여행 시작 전이면 동일 요청을 자동 재모집한다. 시작 이후에는 재모집하지 않는다. 제안이 없어도 별도 배정·매칭 보장은 없다. 여행자가 취소하거나 날짜를 바꿔 새로 요청한다.
  • 확정 후 날짜·인원 변경은 기존 예약 취소 후 새 요청. 여행자가 앱에서 시작 전에 취소하면 기존 메이트 수수료 전액 반환 대상으로 자동 접수한다.
  • 일반 취소는 예약에 기록된 첫날 시작 시각 전까지만 가능하다. 시작 이후 중단·취소 및 실제 미만남·지연은 노쇼 접수 또는 별도 CS로 확인한다. 채팅 합의 시각이 바뀌어도 일반 취소 차단은 예약 시각 기준이다.
  • 수수료 결제로 확정되면 양쪽 모두 먼저 채팅할 수 있다. 여행 완료·예약 취소 또는 마지막 날 24:00(한국 시간) 중 먼저 발생하는 시점부터 읽기 전용. 날짜·인원 변경은 채팅만으로 처리하지 않는다.

취소·반환

  • 여행자가 취소하면 메이트 수수료 전액 반환. 앱의 일반 취소는 별도 문의 없이 운영팀 반환 대상으로 자동 접수하며 실제 PG 취소와는 별개다.
  • 메이트 귀책 취소는 원칙적으로 수수료 미반환. 사고·질병·악천후 등 불가피한 사유만 운영팀 검토 후 반환한다. 악천후가 예상되면 시작 전 취소를 유도한다.
  • 여러 날 중 일부 진행 후 중단: 반환이 인정되는 사유에 한해 미진행 날짜분만 반환한다. 일부라도 진행한 당일은 제외한다. 메이트 귀책 미반환에는 미진행 일수 계산을 적용하지 않는다.
  • 내부 CS 계산: 실제 납부 수수료 × 반환 대상 일수 ÷ 전체 동행 일수. 날짜별 동일 배분을 사용하며 원 미만은 최종 금액에서 반올림하고 원래 납부액을 초과하지 않는다. 3일 수수료 60,000원, 1일 진행 후 2일 반환 인정 시 40,000원. 사용자 앱에는 부분 반환 계산기를 추가하지 않는다.
  • 신청 기한: 취소·노쇼·중단 발생일로부터 7일 이내. 사유와 확인 자료를 함께 접수하며 부족하면 보완 요청. 공식 기상정보로 확인되는 악천후는 첨부 생략 가능.
  • 필요한 자료가 모두 접수된 날부터 3영업일 이내 검토 결과를 이메일로 안내. 실제 결제 취소·입금 소요 시간은 별도 안내한다.
  • 운영팀이 PG 관리자 화면에서 취소·부분 취소하고 실제 성공 확인 후 운영 웹에 금액·완료 상태·확인 번호를 기록한다. 자동 PG 환불은 MVP 범위 밖이다.

노쇼·지각

  • 여행자 무응답 노쇼: 약속 시각부터 30분 대기, 앱 채팅 연락 2회 이상, 응답 없으면 접수 후 떠날 수 있다. 운영팀이 대기·연락 사실을 확인하면 수수료 전액 반환.
  • 여행자가 지각을 알리면 약속 시각부터 최대 60분 대기. 이후에도 미도착이면 ‘지각 연락 후 60분 초과’로 종료 접수 후 떠날 수 있다. 운영팀 확인 후 전액 반환.
  • 접수에 실제 합의한 장소·시각을 기재한다. 접수 시 현재 위치와 채팅 기록을 확인하며 위치 확인 실패 시 자료 첨부로 대체한다. 현재 위치 한 번만으로 30/60분 대기를 자동 인정하지 않고 운영팀이 기록을 종합 확인한다.
  • 여행자 지각은 기존 종료 시각·여행비 유지, 지각한 만큼 동행 시간 감소.
  • 메이트 지각은 여행자가 무료 연장 또는 부족한 시간 비례 여행비 감액을 선택한다. 정책 안내·채팅 합의로 처리하고 분쟁은 CS 확인. 메이트 지각 전용 자동 취소 기준은 두지 않는다. 여행비 감액과 무관하게 기존 플랫폼 수수료 유지.
  • 현금 지급 시점·날짜별 지급 및 식비·교통비·입장료 등의 포함·부담은 당사자 채팅 합의. 비용별 입력 필드나 상세 비용 정책은 앱에 추가하지 않는다. 메이트 지각 보상은 채팅 조건 변경 금지의 예외이며 플랫폼이 여행비를 자동 환불하지 않는다.

가입·메이트 심사

  • 예약자와 메이트는 만 19세 이상. 미성년 참여자는 성인 보호자와 동반하며 단독 동행은 받지 않는다.
  • 메이트는 안내받을 이메일 필수. 이미 인증된 계정 이메일은 그대로 사용하고 없으면 입력·인증한다. 연락처·이메일은 공개 프로필에서 제외한다.
  • 운영팀이 본인 확인과 필요한 자격을 수동 검토한다. 필요한 자료 접수 완료 후 3영업일 이내 결과 안내.
  • 사진·활동 이름·자기소개·지역·언어 등 승인 후 변경은 모두 재심사한다. 재심사 중 기존 승인 프로필·활동 권한을 유지하며 승인 후만 수정 내용 반영. 거절·보완 시 사유 안내 후 수정·재신청 가능, 기존 승인은 유지한다.
  • 신고만으로 자동 정지하지 않는다. 운영팀 확인 후 제한하되 폭력·위협 등 긴급 안전 사안은 조사 중 임시 제한 가능. 기존 예약은 사유·안전을 확인해 예약별 진행 여부를 정하고 양측에 안내한다. 제한 사유 이메일에 회신하면 CS가 재검토하며 별도 이의제기 기능·기한은 두지 않는다.

CS·탈퇴

  • 별도 CS에서 예약 정보를 확인하며 상담한다. 예약 상세에서 문의에 예약을 자동 연결하는 기능은 추가하지 않는다. 운영 웹에서 내용·첨부 자료·처리 상태 관리, 답변은 이메일, Slack은 새 접수 알림 전용이다. 운영시간·주말 야간 대응 제한은 별도 고지하지 않는다.
  • 진행 중 예약(결제 대기·확정·동행 중), 본인의 수수료 반환 처리 중, 본인이 당사자인 예약 분쟁 처리 중이면 탈퇴 제한. 여행자는 상대 메이트의 반환 때문에 제한하지 않는다. 통합 계정이 본인 메이트 역할의 반환 채무·채권을 가진 경우 모드 전환으로 우회할 수 없다.
  • 공개 요청·미선택 제안·등록 및 재심사 대기·일반 문의만으로 탈퇴 제한하지 않는다. 탈퇴 시 종료한다. 거래·분쟁 보존 기록과 삭제할 개인정보는 서버에서 분리한다.

홈페이지 알림 설정

  • 가입 방법 선택 화면에는 동의 체크박스를 표시하지 않는다. 이메일 가입 화면의 이메일 입력란 아래, 인증번호 받기 버튼 위에만 광고성 이메일 수신 선택 동의를 기본 미선택으로 제공한다. 별도 안내 문구 없이 선택 동의 체크박스만 표시한다. 미동의 상태에서도 가입 가능하며 이메일 인증 성공 시 저장한다. 소셜 신규 가입은 별도 동의 단계 없이 광고 수신 OFF로 저장하고 이메일 가입 중 선택값을 이어받지 않는다. 이메일·소셜 로그인은 기존 동의를 유지한다. 가입 후 마이에서 동의·철회할 수 있다.
  • 마이 → 설정 → 알림 설정에서 제안·예약·채팅 소식 이메일(기본 켜짐), 광고성 이메일(기본 꺼짐)을 변경한다. 고객·메이트 및 한국어·영어 화면이 설정을 공유한다. 알림함은 이메일 설정과 관계없이 유지하며 인증 메일은 별개다.
  • MVP는 홈페이지 알림함과 이메일 설정만 제공한다. 브라우저 푸시·SMS·야간 광고 동의·조용한 시간·세부 유형별 설정은 제외하고 야간 광고 이메일은 보내지 않는다. 알림 종류와 발송 정책의 상세 목록은 확장 검토 자료다.
  • 현재는 reeltrip-notification-preferences-v1에 수신 여부·변경 시각·변경 위치·채널·정책 버전을 저장하며 탈퇴 시 삭제한다. 실제 이메일은 발송되지 않는다. 실서비스는 계정별 서버 동의·철회 이력, 검증된 수신 이메일과 발송 직전 설정 확인이 필요하다.

구현 및 개발 인계

로컬 시제품 보완: 날짜별 복수 요청 보존과 전환, 예약 확보·겹침 차단, 제안 철회, 확정 직후 양방향 채팅, 시작 시각 취소 제한, 여행자 취소 반환 접수, 본인 반환·분쟁 탈퇴 제한, 메이트 이메일 인증 시연·만 19세 확인·수정 재심사, CS 자료 첨부·접수 시 위치 확인 및 운영 처리 기록.

실서비스 연결 필수: 사용자별 인증·본인/연령/자격 확인·이메일 발송 및 검증, DB의 메이트/여행자 날짜 고유 제약과 원자적 선택·결제·취소, 앱 종료 중 기한 만료 작업, 실제 PG 결제 및 취소 확인, 안전한 첨부 업로드·접근 권한, 실제 채팅·문의 저장·이메일/Slack 발송, 거래·분쟁 기록 보존·삭제 정책, 운영 처리자 감사 로그. 브라우저 저장·시연 인증은 이를 대체하지 않는다.

  • 공개 HTTPS Shorts/Reels 링크와 장소 확인을 지원한다. 실제 추출은 미연동이다.
  • 요청은 최소 48시간 전·최대 7일이다. 자유 견적은 지역 입력과 기간만으로 시작한다. 내 여행은 날짜 순서와 하루 최대 20곳을 검사한다. 지역별 실제 메이트 공급·영업 가능 여부는 서버 연결 후 검증한다. 숙박 일수는 기간이며 숙소나 24시간 동행을 포함하지 않는다. MVP 영어 동행은 하루 4시간 고정이며 메이트는 일행 전체 금액만 입력한다. 날짜·인원·기존 일정은 요청 스냅샷 그대로 유지한다. 자유 여행에만 날짜별 코스를 입력한다.
  • 같은 요청에 복수 제안을 보존한다. 동일 메이트의 유효한 제안은 수정·재발행할 수 없다. 만료 후 재발행 시에만 교체하며 고객이 선택한 버전·금액을 예약에 고정한다. 채팅은 일정·금액을 변경하지 않는다.
  • 여행자 선택만으로 확정하지 않는다. 선택된 메이트의 매칭 수수료 10% 결제 검증 후에만 확정한다.
  • 여행비는 현장에서 직접 현금으로 지급하며 앱에서 별도 수령 확인을 요구하지 않는다.
  • 확정 전 철회와 확정 후 즉시 취소를 분리한다. 플랫폼은 여행비 자동 환불을 제공하지 않는다.
  • 확정 기한은 선택 후 24시간과 출발 시각 중 빠른 시각이다. 결제 유예·노쇼·취소·분쟁은 위 MVP 정책을 적용한다. VAT 처리는 별도 확정한다. 이전 자동 환불률을 적용하지 않는다.
  • 닉네임 중복 금지: NFKC·공백 제거·소문자 기준. 자신의 기존 이름 유지 허용. 변경 후 재확인과 저장 직전 재검사. 실제 서버 UNIQUE 제약은 별도 구현한다.

메이트 활동과 확정 관리

메이트 GNB: 여행 찾기 / 내 활동 / 채팅 / 마이. 내 활동은 보낸 제안 / 예약 두 탭과 건수로 구분한다. 선택된 제안은 예약 탭으로 이동하고 수수료 결제 대기·예약 확정·완료·취소를 구분한다. 예약이 있으면 예약 탭을 기본으로 열며 사용자가 선택한 탭은 URL에 보존한다. 각 탭의 빈 상태는 아이콘·안내·버튼을 중앙 정렬한다. 결제 대기 상태의 여행 찾기 카드·내 활동 카드·선택된 제안·예약 상세에는 진행 불가(보조) → 수수료 확인하고 결제하기(주 실행)를 함께 표시한다. 결제 폼의 주 실행은 결제하고 예약 확정으로 표시한다. 진행 불가는 사유 입력 후 진행 거절하기로 제출하며 자동 재모집 안내를 제공한다. 다건 예시 예약은 상세 열람 전용이므로 실행 버튼을 비활성화한다. 수수료 금액·상태 확인과 결제는 해당 예약 상세에서 진행한다. 기존 화면 ID와 저장 키는 유지한다.

선택 시 feeDeadline을 고정한다. 시제품은 선택 후 24시간과 출발 시각 중 빠른 기한을 사용한다. 렌더링과 결제 시 만료를 확인하며 앱이 닫힌 동안 서버 알림이나 자동 작업은 실행되지 않는다. 확정 전 메이트 진행 불가·기한 만료 시 여행 시작 전이면 자동으로 제안 모집을 재개한다. 기존 예약은 bookingHistory에 보존하고 해당 메이트의 제안은 만료시키며 다른 유효한 제안은 즉시 선택 가능하게 유지한다. 여행자에게 해제 사유와 재모집 상태를 안내한다. 여행 시작 시간이 지났으면 자동 재모집하지 않고 일정 변경을 안내한다. 여행자의 직접 철회는 자동 재모집하지 않으며 다른 제안 선택 버튼으로 재개한다.

결제 화면은 약속 금액·수수료 10%·차감 후 금액(기타 비용 차감 전)을 표시한다. 성공 후 예약 상세에서 채팅으로 만날 장소·날짜별 시간·현금 지급 시점을 확인한다. 동행 관리 카드 없이 예약 상세 맨 아래에 예약 취소 텍스트 버튼을 제공한다. 마지막 날 동행 종료 시각 이후에는 여행 완료 확인을 별도의 주요 버튼으로 표시한다. 현금 수령 확인은 요구하지 않는다. 확정 후 취소는 즉시 cancelled로 처리하며 request도 cancelled로 갱신한다. 수수료 반환은 refundStatus=review로 별도 검토하며 예약 취소 완료는 환불 완료를 의미하지 않는다. 노쇼·반환은 위 MVP 정책을 적용하며 실제 PG 연결·세금 처리는 별도 구현한다.

가능 날짜 달력은 제공하지 않는다. 메이트가 가능한 요청에 직접 제안하며, 확정 예약과 날짜가 겹치는 제안은 차단한다. 기존 unavailableDates 저장값은 보존하되 제안 가능 여부에 사용하지 않는다. 실서비스는 서버 소유권 검사, 예약 중복 방지, 기한 만료와 PG 웹훅 경합 처리, 결제 멱등성, 금액·통화·주문 검증을 구현해야 한다.

채팅 정책

  • 시작: 메이트가 매칭 수수료를 결제해 확정되면 양측 모두 먼저 1:1 메시지를 보낼 수 있다. 결제 전에는 양측 모두 메시지를 보낼 수 없다.
  • 이용 기간: 여행이 확정된 동안 마지막 날 24:00(Asia/Seoul, 다음 날 00:00)까지 대화할 수 있다. 여행 완료 처리 시 즉시 종료한다.
  • 종료: 여행 완료, 이용 기간 종료 또는 예약 철회·취소 시 읽기 전용으로 전환한다.
  • 메시지: 텍스트 1~1,000자만 지원한다. 빈 메시지는 보낼 수 없으며 사진·파일 첨부는 지원하지 않는다.
  • 예약 조건: 만날 장소·시간을 확인하는 용도다. 채팅 합의만으로 선택한 일정·금액은 변경되지 않는다.
  • 확정: 예약은 메이트의 10% 매칭 수수료 결제 후 확정되며 양측 모두 대화를 먼저 시작할 수 있다. 여행비는 현장에서 현금으로 직접 지급한다.

신고·차단 MVP

채팅방 더보기에서 사용자 신고·차단·해제를 제공한다. 신고는 사유 선택, 선택 상세(기타는 필수, 최대 1,000자)를 저장하며 같은 신고자의 같은 대화방 중복 신고를 막는다. 차단은 상대 ID 기준으로 다른 대화방에도 적용하고 양쪽 메시지 전송 및 미읽음 표시를 중단한다. 기존 대화와 예약 상태는 유지한다. 설정의 차단한 사용자에서 해제할 수 있다. 빈 목록은 차단 진입 경로를 안내하고, 목록이 있으면 사용자명·차단 중 상태·해제 버튼과 건수를 표시한다. 차단은 예약 취소가 아님을 안내한다. 해제 확인은 취소→차단 해제 순서로 제공하고 취소하면 목록으로 돌아간다. 해제 후 완료 안내와 갱신된 목록을 표시하며 마지막 사용자 해제 시 빈 상태로 전환한다. 상대방의 차단이나 채팅 종료 등 이용 조건으로 해제 후에도 전송이 제한될 수 있음을 확인창에 안내한다. 사용자·메이트 모두 상대를 신고·차단할 수 있다. 운영 웹의 문의·신고·차단에서 한국어·영어 앱의 신고자 역할·대상·사유·상세·시각·대화방 및 현재 차단 목록을 확인하고 새로고침할 수 있다. 차단 해제 후에도 신고 기록은 유지한다. 같은 브라우저·같은 출처의 로컬 저장소로 동작하며 외부 연동은 사용하지 않는다. 서버 연결 시 실제 사용자 ID, 인증·권한, 양방향 전송 차단 및 신고 처리 절차를 구현해야 한다.

가입 방법과 로그인

  • 가입 화면의 ‘이미 계정이 있나요? 로그인’과 게스트 마이의 로그인으로 기존 회원이 진입한다. signup?mode=signin에서 이메일 또는 소셜 로그인을 선택하고, signup-email?mode=signin에서 이메일 → 코드 확인 순서로 진행한다. 언어 전환과 뒤로 가기에서도 로그인 모드를 유지한다. 현재는 시연 인증이며 실제 계정 조회·이메일 발송·서버 인증은 연결되지 않았다.
  • 처음 방문한 여행자는 Google·카카오·네이버 간편가입, 이메일 가입, 가입 없이 둘러보기 중 하나를 선택한다.
  • 간편가입 버튼에는 제공사 로고와 이름을 함께 표시한다. Google은 흰 바탕과 다색 G, 카카오는 노란 바탕과 말풍선, 네이버는 초록 바탕과 N으로 구분한다.
  • 미리보기에서는 간편가입 버튼을 한 번 누르면 즉시 로그인 상태로 홈에 진입한다. 실제 서비스에서는 각 제공사의 인증이 성공한 뒤 로그인 처리한다.
  • 이메일 가입은 주소 입력 → 인증 코드 입력 → 가입 완료 순서로 진행한다. 미리보기에서는 시연용 코드로 확인하며, 실제 이메일 발송·검증은 서비스 연동 시 구현한다.

가입 언어와 로고

가입 화면에서 한국어·영어·중국어 간체·일본어를 선택할 수 있다. 언어 설정에는 현재 언어 이름을 표시하고 선택 목록에는 선택 표시를 둔다. 선택 즉시 가입 화면에 적용하고 가입 후에도 같은 언어로 앱을 연다. 중국어 가입 로고에는 ‘映旅’, 일본어 가입 로고에는 ‘リールトリップ’을 표시한다. 게스트도 마이에서 언어를 변경할 수 있다.

게스트 열람 범위와 가입 안내

  • ‘가입 없이 둘러보기’를 선택하면 발견 홈을 연다. 발견·내 여행·메이트·채팅·마이 탭 이동, 추천 경로와 예시 장소 열람, 공개 예시 열람은 가입 없이 허용한다. 실제 제안 상대 메이트 프로필은 회원 전용이다.
  • 장소 추가·저장, 여행 일정 만들기·수정, 메이트 요청 등 회원 기능을 실행할 때 가입을 안내한다. 탭을 여는 것만으로는 안내를 띄우지 않는다. 게스트의 개인 데이터는 저장하지 않는다.
  • 가입 안내에는 여행을 연상시키는 이미지나 아이콘과 친근한 문구를 사용한다. ‘가입하기’는 가입 화면으로, ‘계속 둘러보기’는 직전에 보던 공개 화면으로 연결한다.
  • 게스트 마이에는 게스트 상태, 가입 버튼, 언어 설정을 표시한다. 프로필 편집과 별도 이용안내 메뉴는 제공하지 않는다. 알림 진입점을 마이 메뉴에 중복 배치하지 않는다.
  • 추천 경로의 장소 카드는 사진 옆에 장소명과 주소를 묶어서 표시한다. 좁은 화면에서도 긴 주소가 카드 안에서 줄바꿈되도록 한다.

가입 화면 미리보기

프로젝트 최상위 index.html을 브라우저에서 직접 열면 가입 화면으로 진입할 수 있어야 한다. 별도 로컬 서버를 시작하거나 포트 주소를 입력하는 절차는 필요하지 않다.

가입 시 임시 닉네임

회원가입을 완료하면 가입 화면에서 선택한 언어로 임시 닉네임을 한 번 부여한다. 이후 앱 언어를 바꿔도 부여한 닉네임은 유지하며, 회원은 프로필에서 직접 변경할 수 있다.

한국어·영어·중국어 간체·일본어 각각 20개의 후보 중 하나를 고르고, 공백 한 칸 뒤에 0000~9999 범위의 숫자 네 자리를 붙인다. 앞자리 0도 표시한다(예: 구름 0427). 이미 사용 중인 조합이면 다른 조합을 부여한다.

후보는 구름·별·달처럼 짧고 독립적으로 쓰이는 명사를 우선한다. 종이지도처럼 여러 명사를 이어 붙인 설명형 이름은 피하고, 각 언어에서 같은 뜻을 자연스럽게 표현하는 단어를 고른다.

메이트 등록·승인

마이에서 메이트로 등록하기 → 전국 시·도 전체 또는 시·군·구 활동 지역 복수 선택(일반구가 있는 시는 구 단위, 제주는 제주시·서귀포시, 하위 시·군·구가 없는 세종은 전체)/영어·일본어·중국어·한국어 중 언어 1개 이상 복수 선택 → 필수 프로필 사진·직접 입력하는 활동 이름(사용자 닉네임과 메이트 활동 이름의 통합 중복 검사, 2~20자)·통합 자기소개(10~1,000자) → 비공개 휴대폰 번호·6자리 문자 인증 UI(시연용 123456, 실제 발송 없음, 유효시간 3분, 재전송 간격 30초, 5회 실패 제한) → 입력 확인·필수 동의 → 심사 요청. 활동 지역 선택은 하단 바텀시트로 제공하며 제목·시도 선택과 선택 요약·완료 버튼은 고정하고 지역 목록만 스크롤한다. 지역 버튼은 기본 4열, 360px 미만에서는 3열이며 내용을 약 90% 크기로 압축하고 최소 40px 터치 영역을 유지한다. 단계 진행률·이전·닫기·자동 임시 저장을 제공한다. 필수 사진은 JPG/PNG/WebP 1MB 이하로 미리보기·교체·삭제하며 브라우저에 저장한다. 동네와의 인연·걷는 속도/휴식·가능한 도움은 자기소개 한 영역에 자유롭게 작성하며 기존 개별 입력값은 빈 줄로 합쳐 보존한다. 관련 경험·자격 입력란은 제공하지 않는다. 공개 미리보기에는 본인 작성·미검증을 표시하고 연락처을 제외한다. 실제 운영의 확인 표시는 항목별 근거 종류·검토자·확인 일시와 유효기간 기록이 있어야 하며, 등록 승인 자체로 인증 배지를 부여하지 않는다. 완료 동행·후기는 실제 완료 예약과 연결된 기록만 집계한다. 시제품에는 확인 및 동행 기록 없음으로 표시한다. 자택 주소와 실제 증빙은 시제품에서 수집하지 않는다.

draft → pending → approved 또는 needs_info/rejected. 보완 요청과 거절은 사유 필수이며, 신청자는 수정 후 pending으로 재제출할 수 있다. 심사 중에는 제출 내용을 읽기만 가능하다. 여행자 마이의 등록 카드는 미등록·심사 중·승인 완료·보완 요청·승인 거절 상태별 안내를 표시한다. 심사 중에는 제출 내용 확인, 보완 요청·거절은 사유 확인과 수정 후 재제출로 연결한다. 승인 완료 카드는 메이트 모드로 전환해 여행 요청 화면으로 연결한다. 승인 후에만 메이트 모드 전환과 활동을 허용한다. 메이트 마이의 프로필 편집에서 사진·활동 이름·자기소개를, 활동 정보 수정에서 분야·복수 지역·언어를 변경한다. 수정 내용을 재심사하며 승인 시 반영하고 취소 시 폐기하며, 이름 변경은 중복 확인이 필요하다. 승인 상태와 비공개 연락처·심사 정보는 유지한다. 여행자 기능은 계속 이용 가능하다. 신청 시 결제하지 않으며 여행자 선택 후 10% 매칭 수수료 결제 → 예약 확정, 여행비 현장 현금 직접 지급 규칙을 유지한다.

운영 웹의 메이트 등록 심사에서 신청서·비공개 연락처을 검토하고 확인 체크 후 승인한다. 실제 운영에서는 본인 확인·자격 진위·계약 검증 기록이 있어야 승인 가능하다. 필요한 자격을 수동 확인하고 자료 접수 완료 후 3영업일 이내 심사 결과를 안내한다. 공개 프로필에는 연락처·증빙·심사 사유를 포함하지 않는다.

현재는 reeltrip-mate-application-v1에 하나의 시연 신청서를 저장하고 같은 출처·브라우저의 앱/운영 웹에서 공유한다. 한국어·영어 화면은 같은 신청서를 사용한다. 승인 상태를 기존 reeltrip-prototype-access-v1 권한에 반영한다. 활동 이름은 랜덤 부여하지 않으며 단계 진행과 제출 시 통합 목록을 재검사한다. 현재 중복 검사는 동일 브라우저의 시연 데이터에 한정되며 실서비스에서는 사용자 닉네임과 메이트 이름을 통합한 서버 고유 제약이 필요하다. 실제 사용자별 DB·인증·실제 SMS 발송 및 서버 검증·서류 업로드·알림·다중 사용자 처리는 미구현이다. 실제 승인 API는 관리자 권한·pending 상태·필수 검증·신청 버전을 서버에서 확인하고 역할 부여와 심사 로그를 원자적으로 저장해야 한다. 모든 메이트 활동 API는 서버에서 승인 상태를 검사해야 한다.

공개 여행 요청과 메이트 탐색 정책

2026-11-23 결정. 여행자가 명시적으로 제안 받기에 동의한 요청만 모든 승인 메이트에게 공개한다. 작성 중인 여행과 개인 장소 보관함은 비공개다. 초기에는 지역 불일치를 이유로 열람을 제한하지 않으며 요청별 전체 제안 수 상한을 두지 않는다. 동일 메이트의 유효한 제안 중복 제한은 유지한다.

  • 흐름: 여행자가 공개 항목 확인·동의 → 승인 메이트가 여행 찾기에서 탐색 → 복수 메이트의 일정·가격 제안 → 여행자 비교·선택 → 신규 제안 접수 중단 → 선택 메이트의 10% 수수료 결제 → 확정. 여행비는 현장 현금 직접 지급한다.
  • 공개 항목: 날짜·지역·인원·안내 언어·공개 방문 장소·요청사항. 연락처, 정확한 숙소 주소, 개인 여행 제목, 계정 ID, 비공개 메모는 공개 응답에서 제외한다. 자유 입력에 개인정보를 적지 않도록 사전 안내하고 서버에서 검출·수정 요청을 처리한다. 클라이언트에서 숨기는 것만으로 보호했다고 간주하지 않는다.
  • 기본 정렬: 활동 지역과 전 일정 가능 여부 모두 일치 → 날짜 가능 → 지역 일치 → 최신 공개 순 → 요청 ID 순. 지역 미입력·인식 불가 요청도 목록에 남긴다. 실서비스는 표준 지역 코드로 매칭하고 날짜는 한국 시간 기준으로 예약 충돌과 메이트 휴무를 확인한다. 지역·날짜 필터는 선택사항이며 초기 기본값은 전체 공개 요청이다.
  • 상태: requested/quoted만 탐색에 노출. 여행자 선택·철회·마감 시 목록에서 제외하고 제출 시 상태를 재검사한다. 선택 대기 만료로 요청이 다시 열리면 재노출한다. 선택과 제안 제출 경합은 서버 트랜잭션으로 처리한다.
  • 성장 단계: 우선 지역·날짜·언어 적합도에 따라 노출 순서와 알림 대상을 좁힌다. 요청당 제안 수, 첫 제안 도착 시간, 무제안 요청 비율을 관찰한 뒤 제안 수 상한 또는 적합 메이트 우선 공개·점진 확대를 도입한다. 회원 수만으로 제한하지 않으며 수치 기준은 운영 데이터로 결정한다. 초기 자동 푸시·독점 배정은 제공하지 않는다.

서버 개발 계약: 공개 요청 조회·상세·제안 API 모두 승인된 메이트 권한을 서버에서 검사한다. 목록과 상세는 허용 필드만 반환하고 검색·페이지네이션에도 같은 공개 상태 조건을 적용한다. 여행자 본인만 공개·철회·선택 가능하다. 비승인·정지 계정의 조회 및 제출을 거절한다. 개인 여행 원본과 공개 스냅샷을 분리하고 공개 시점·동의 버전·종료 사유를 기록한다.

현재 구현: 로컬 날짜별 복수 요청과 기존 저장 키를 유지한다. 공개 동의 안내, 승인 메이트 화면 접근, 공개 상태 필터, 지역 문자열·예약 충돌 기반 정렬을 시연한다. 요청 자유문은 목록에 노출하지 않는다. 실제 다중 사용자 피드·표준 지역 매칭·휴무 관리·개인정보 검출·서버 권한·알림은 미연결이며 완료본으로 표시하지 않는다.
