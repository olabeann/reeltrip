서비스 모두
모바일 앱입니다.

고객은 휴대전화에서 영상을 발견하고 장소를 모아 여행합니다. 이전 설계과 릴트립은 모바일 앱이라는 동일한 형태에서 서비스 범위가 달라지는 대안이며, 앱과 웹을 비교하는 안이 아닙니다. 모든 화면은 한국어 검토본입니다.

앱 정보 구조

이전 설계 · 직접 계획하는 여행

  • 발견 → 영상 링크 입력 → 분석 상태 → 장소 후보 확인
  • 내 장소 → 직접 추가·지점 수정·필수 방문 → 일정 만들기
  • 내 여행 → 저장 일정 → 시간·순서 편집 → 공유
  • 마이 → 데이터 관리 / 도움말·문의 / 이용·개인정보 안내

릴트립 · 가이드와 완성하는 여행

  • 발견·내 장소 → 이전 설계과 동일한 장소 수집 흐름
  • 가이드 → 프로필 → 내 일정으로 요청 → 응답 대기
  • 내 여행 → 요청·견적 → 결제 → 예약 상세 → 대화·취소·후기
  • 마이 → 데이터 관리 / 도움말·문의 / 이용·개인정보 안내

요청·예약의 상태는 내 여행에서 추적합니다. 하위 화면에는 이전 단계로 돌아가는 상단 버튼을 두고 현재 작업에 해당하는 하단 탭을 강조합니다. 기존 화면 번호 A-01~A-14, B-01~B-30은 유지합니다.

화면 구성과 조작 정책

  • 기준 폭 390px, 320~430px 화면 대응. 큰 모니터에서도 최대 430px 모바일 미리보기로 표시합니다.
  • 상단 앱 바 → 본문 한 열 → 주요 행동 버튼 → 하단 탭. 지도와 목록을 좌우로 나누지 않습니다.
  • 발견 화면의 첫 행동은 영상 링크 붙여넣기입니다. 장소 선택·일정 저장·요청 제출 등 주요 버튼은 한 화면에서 명확하게 구분합니다.
  • 하단 안전 영역을 반영하고, 키보드가 표시되면 입력과 제출 버튼이 가려지지 않게 스크롤합니다. 실제 기기 검증이 필요합니다.
  • 입력 검증 오류는 해당 입력 주변에 표시합니다. 처리 중·빈 결과·실패·재시도·저장 실패 상태를 제공합니다.
  • 이동 중 연결 끊김을 고려해 저장 일정의 읽기 전용 사본을 제공하는 방향으로 설계합니다. 최신 영업·예약 상태와 동기화 시각을 구분합니다.
  • 고객의 클립보드를 자동으로 읽지 않습니다. 직접 붙여넣기 또는 사용자가 실행한 공유 동작만 받습니다.

개발 인계와 출시 확인

기존 HTML·CSS·JavaScript는 앱의 화면과 업무 흐름을 검토하는 시제품입니다. 설치 파일, 실제 계정·분석·지도·결제 연동, 앱스토어 제출 빌드는 포함하지 않습니다. 모바일 개발 단계에서 구현 기술을 선정하고 기존 화면 번호·입력 규칙·정책·상태 전이를 기준으로 이식합니다.

  1. 아이폰·안드로이드 각각 앱 실행, 뒤로가기, 안전 영역, 큰 글자, 스크린리더, 키보드 가림 확인
  2. 공유 링크 수신, 앱이 꺼진 상태의 링크 열기, 지원하지 않는 링크와 중복 분석 처리 확인
  3. 권한 허용·거절·철회, 네트워크 단절·복구, 앱 종료·재실행 확인
  4. 릴트립은 결제 인증 복귀·중복 방지·만료 견적·취소·환불·알림 확인
  5. 출시 시점에 배포 계정, 서명, 개인정보 고지, 스토어 심사와 결제 분류를 공식 기준으로 별도 검토

위 항목은 개발 요구사항이며 모두 구현·통과했다는 의미가 아닙니다. 기존 법적 운영 전제와 서비스 정책 초안은 그대로 적용합니다.
