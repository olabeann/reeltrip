릴트립 기획·명세

서비스 기획

영상과 직접 입력으로 장소를 모으고, 내 여행을 만든 뒤 현지 메이트의 제안을 비교하는 매칭 서비스다.

탭별 역할

  • 발견: 영상 링크로 장소 찾기 → 선택한 장소를 보관함에 저장. 바로 일정에 넣지 않는다.
  • 채팅: 여행 요청·메이트별 대화 목록. 제안 상세에서 상담을 시작하고 예약 후에도 이력을 유지한다. 최근 메시지·시각·상태·역할별 미읽음 표시. 종료된 대화는 읽기 전용. 실제 전송 없는 로컬 시제품.
  • 내 여행: 여행 생성 카드·간단한 저장한 장소 진입·다가오는 여행/지난 여행 목록. 여행 상세는 상단 정보 수정·전체 공유, 지도, 날짜별 일정 시트, 순서 번호와 거리 안내, ＋ 메뉴(저장한 장소·새 장소·메모)로 구성한다. 날짜별 메모를 저장하고 출발일 수정 시 모든 날짜를 함께 이동한다. 새 여행 생성·선택 후 상세 안에서 날짜·장소·순서·체류시간·메이트 요청을 관리한다. 여행별 일정은 분리 저장하고 장소 보관함은 공유한다. 일정에서 빼도 보관함에는 유지.
  • 메이트: 받은 제안 관리 / 자유 견적 받기. 자유 견적은 여행 지역·출발일·기간(당일~6박 7일)·인원으로 요청하며 장소 목록은 필요 없다. 내 여행에서는 날짜별 장소가 담긴 전체 여행으로 요청한다. 두 경로 모두 공개 요청 후 복수 제안을 비교·선택한다.
  • 마이: 프로필 편집, 진행 중인 여행과 활동 바로가기. 설정 아이콘 안에 언어·모드 전환, 도움말·약관·데이터 관리.

확정 흐름

여행 공개 → 메이트들의 일정·가격 제안 → 여행자 선택·예약 요청 → 메이트 확정 대기 → 메이트가 10% 매칭 수수료 결제 → 예약 확정 → 현장에서 여행비 전액 현금 직접 지급.

240,000원 여행이면 메이트는 플랫폼에 24,000원을 선결제하고, 여행자는 메이트에게 240,000원을 현금으로 직접 지급한다. 플랫폼은 여행비를 수납·송금하지 않는다.

현재 구현 범위

고객·메이트 동일 앱, 운영자는 별도 웹. 한국어·영어 로컬 시제품. 여러 여행·1개 활성 공개 요청을 유지하며, 내 여행 전체 일정 또는 자유 견적 요청을 공개한다. 기간과 요청 유형은 제안·예약까지 스냅샷으로 보존한다. 복수 제안과 가이드별 재발행은 지원한다. 실제 영상 분석·인증·DB·PG·푸시·다중 사용자 동기화는 미구현이다.

기능 명세

B-01 홈과 링크 입력

화면 열기

입력
공개 Shorts/Reels HTTPS URL 1개, 최대 2,048자
규칙
호스트·경로 허용 목록 검사. 비공개·삭제 영상은 분석 실패 처리. 임의 URL 서버 접근 금지.
행동·전이
유효한 링크 입력 또는 샘플 시작 → processing
상태
기본 / 잘못된 URL / 처리 중 / 사용량 제한
인수 기준
허용되지 않은 링크는 이동하지 않고 입력 오류 표시. 샘플은 네트워크 없이 예시 데이터 로드.

B-02 장소 분석 상태

화면 열기

입력
extraction_job_id, 원본 URL
규칙
실서비스는 큐 비동기 처리·중복 요청 키 사용. 60초 초과 시 대기 안내, 3분 초과 실패 전환(제안).
행동·전이
처리 완료 → results / 실패 시 manual 또는 home
상태
대기열 / 분석 중 / 부분 성공 / 성공 / 실패
인수 기준
부분 성공 시 발견한 장소는 유지. 실패 시 직접 장소 추가 경로 제공. 프로토타입은 1.4초 시뮬레이션.

B-03 지도에서 영상 속 장소 확인

화면 열기

입력
place_id, source_url, 지점 후보, 사용자 선택
규칙
정확한 좌표가 있는 후보만 지도에 표시. 미확인 후보는 별도 목록. place_id 기준 중복 제거. 추출 실패·부분 성공을 구분.
행동·전이
장소 선택 → 저장한 장소(board) → 날짜별 일정 만들기
상태
전체 / 음식 / 카페 / 쇼핑 / 공원 / 미확인 / 결과 없음
인수 기준
저장은 보관함만 갱신하며 날짜별 일정을 변경하지 않는다. 중복 저장 방지. 결과가 없어도 직접 장소 추가 가능.

B-04 장소 직접 추가

화면 열기

입력
장소명 2~80자, 주소 5~160자, category
규칙
자동 추출 실패의 대체 경로. 실서비스는 장소 검색 API의 canonical ID로 선택; 자유입력은 사용자 입력 상태로 보관.

잘못된 길이 입력은 차단. 직접 추가 장소를 추출 확인 장소로 표시하지 않음.

운영 정책

  • 공개 HTTPS Shorts/Reels 링크와 장소 확인을 지원한다. 실제 추출은 미연동이다.
  • 요청은 최소 48시간 전·1~4명·최대 7일이다. 자유 견적은 지역 입력과 기간만으로 시작한다. 내 여행은 날짜 순서와 하루 최대 20곳을 검사한다. 지역별 실제 메이트 공급·영업 가능 여부는 서버 연결 후 검증한다. 숙박 일수는 기간이며 숙소나 24시간 동행을 포함하지 않는다. 견적은 전체 기간 총 동행 시간으로 계산한다.
  • 같은 요청에 복수 제안을 보존한다. 동일 메이트의 재발행만 교체하며 고객이 선택한 버전·금액을 예약에 고정한다.
  • 여행자 선택만으로 확정하지 않는다. 선택된 메이트의 매칭 수수료 10% 결제 검증 후에만 확정한다.
  • 현금 수령 상태는 예약 확정·여행 완료와 별개다. 자동 수령 처리하지 않는다.
  • 확정 전 철회와 확정 후 취소 검토를 분리한다. 플랫폼은 여행비 자동 환불을 제공하지 않는다.
  • 수수료 결제 유예시간·노쇼·취소 시 반환·VAT 및 분쟁 정책은 미확정이다. 이전 자동 환불률을 적용하지 않는다.
  • 닉네임 중복 금지: NFKC·공백 제거·소문자 기준. 자신의 기존 이름 유지 허용. 변경 후 재확인과 저장 직전 재검사. 실제 서버 UNIQUE 제약은 별도 구현한다.

가입 방법과 로그인

  • 처음 방문한 여행자는 Google·카카오·네이버 간편가입, 이메일 가입, 가입 없이 둘러보기 중 하나를 선택한다.
  • 간편가입 버튼에는 제공사 로고와 이름을 함께 표시한다. Google은 흰 바탕과 다색 G, 카카오는 노란 바탕과 말풍선, 네이버는 초록 바탕과 N으로 구분한다.
  • 미리보기에서는 간편가입 버튼을 한 번 누르면 즉시 로그인 상태로 홈에 진입한다. 실제 서비스에서는 각 제공사의 인증이 성공한 뒤 로그인 처리한다.
  • 이메일 가입은 주소 입력 → 인증 코드 입력 → 가입 완료 순서로 진행한다. 미리보기에서는 시연용 코드로 확인하며, 실제 이메일 발송·검증은 서비스 연동 시 구현한다.

가입 언어와 로고

가입 화면에서 한국어·영어·중국어 간체·일본어를 선택할 수 있다. 언어 설정에는 현재 언어 이름을 표시하고 선택 목록에는 선택 표시를 둔다. 선택 즉시 가입 화면에 적용하고 가입 후에도 같은 언어로 앱을 연다. 중국어 가입 로고에는 ‘映旅’, 일본어 가입 로고에는 ‘リールトリップ’을 표시한다. 게스트도 마이에서 언어를 변경할 수 있다.

게스트 열람 범위와 가입 안내

  • ‘가입 없이 둘러보기’를 선택하면 발견 홈을 연다. 발견·내 여행·메이트·채팅·마이 탭 이동, 추천 경로와 예시 장소 열람, 메이트 목록·프로필 열람은 가입 없이 허용한다.
  • 장소 추가·저장, 여행 일정 만들기·수정, 메이트 요청 등 회원 기능을 실행할 때 가입을 안내한다. 탭을 여는 것만으로는 안내를 띄우지 않는다. 게스트의 개인 데이터는 저장하지 않는다.
  • 가입 안내에는 여행을 연상시키는 이미지나 아이콘과 친근한 문구를 사용한다. ‘가입하기’는 가입 화면으로, ‘계속 둘러보기’는 직전에 보던 공개 화면으로 연결한다.
  • 게스트 마이에는 게스트 상태, 가입 버튼, 언어 설정을 표시한다. 프로필 편집과 별도 이용안내 메뉴는 제공하지 않는다. 알림 진입점을 마이 메뉴에 중복 배치하지 않는다.
  • 추천 경로의 장소 카드는 사진 옆에 장소명과 주소를 묶어서 표시한다. 좁은 화면에서도 긴 주소가 카드 안에서 줄바꿈되도록 한다.

가입 화면 미리보기

프로젝트 최상위 index.html을 브라우저에서 직접 열면 가입 화면으로 진입할 수 있어야 한다. 별도 로컬 서버를 시작하거나 포트 주소를 입력하는 절차는 필요하지 않다.

가입 시 임시 닉네임

회원가입을 완료하면 가입 화면에서 선택한 언어로 임시 닉네임을 한 번 부여한다. 이후 앱 언어를 바꿔도 부여한 닉네임은 유지하며, 회원은 프로필에서 직접 변경할 수 있다.

한국어·영어·중국어 간체·일본어 각각 20개의 후보 중 하나를 고르고, 공백 한 칸 뒤에 0000~9999 범위의 숫자 네 자리를 붙인다. 앞자리 0도 표시한다(예: 구름 0427). 이미 사용 중인 조합이면 다른 조합을 부여한다.

후보는 구름·별·달처럼 짧고 독립적으로 쓰이는 명사를 우선한다. 종이지도처럼 여러 명사를 이어 붙인 설명형 이름은 피하고, 각 언어에서 같은 뜻을 자연스럽게 표현하는 단어를 고른다.

개발 설계

원본: assets/app.js, catalog.js, access.js, revenue.js. 영어는 i18n/build_english.py로 생성한다. 기존 B-* ID와 localStorage 키는 내부 호환성을 위해 유지한다.

  • library: 공통 장소 보관함. trips/activeTripId: 여행별 저장과 선택 상태. board/days: 현재 여행의 날짜별 일정. 기존 단일 여행 데이터는 첫 여행으로 보존한다.
  • request: 공개 여행 스냅샷. requestType(itinerary/free), region, date/endDate, dayCount, days(날짜별 장소)를 포함하고 기존 요청은 하루로 호환한다. proposals: 메이트별 견적 배열. quote: 현재 상세 선택 제안.
  • booking: 선택 제안 스냅샷, feeRate=0.1, feeAmount, feeStatus, paymentMethod=cash, cashStatus.
  • 프로필·읽음 상태·닉네임 디렉터리는 현재 로컬 저장이다. 서버 인증·소유권·개인정보 보호는 별도 구현이다.

서버 연결 계약

여행자 예약 요청은 awaiting_mate_fee. PG 서버 응답·서명 웹훅의 금액/통화/주문/선택 메이트 ID를 대조한 후 confirmed. 클라이언트 성공 값만으로 확정 금지. 서버 가격 스냅샷·트랜잭션·결제 멱등성·취소와 결제 경합 보상 처리를 구현한다. 닉네임 canonical UNIQUE와 소유권 검사는 서버에서 원자적으로 수행한다.

상세 계약·미확정 사항

검증 기준

코드 검사는 브라우저·기기 시각 검증이나 실제 서버 통합 검증을 대체하지 않는다.

  • node tests/startup_checks.cjs: 전체 entry script 초기화·기존 저장 데이터 로드.
  • node tests/navigation_checks.cjs: 한영 경로·닉네임·복수 제안·현금 매칭 상태 전이.
  • node tests/matching_routes_checks.cjs: 장소 저장 분리·두 요청 경로·다일 견적·예약 기간 보존.
  • node tests/access_checks.cjs: 역할별 시연 접근.
  • node tests/google_map_checks.js: 지도 폴백·좌표.
  • python3 tests/static_checks.py: 문서·경로·화면 추적성.
  • 상위 폴더에서 node reeltrip-planning/tests/tower_seed_checks.cjs: 기존 데이터 업그레이드.

미확정 운영 사항

현금 직접 거래와 10% 매칭 수수료는 제품 결정이다. 이 설명만으로 법적 의무나 면제 여부가 확정된 것은 아니다.

실제 운영 주체·계약 상대방·자격·등록·보험·현금 거래 책임·수수료 세금·취소/노쇼 정책은 출시 전에 검토하고 확정한다. 이전 직접 여행 운영 모델의 법적 결론을 그대로 전용하지 않는다.
