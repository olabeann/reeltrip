문구 작성 원칙

  1. 감성적인 표현보다 지금 막힌 일을 먼저 말한다. ‘좋은 하루’ 대신 ‘어느 지점인지’, ‘얼마를 내는지’를 알려준다.
  2. 한국의 지역·시간·가격 지식을 가정하지 않는다. 서울 성수, 한국 현지 시간, 일행 전체 금액처럼 기준을 함께 적는다.
  3. 한 문구에 상태와 다음 행동을 담는다. ‘실패’로 끝내지 않고 공개 링크 재시도·장소 직접 추가 등 실제 경로를 제공한다.
  4. 불안을 자극하거나 한국 방문 전체를 어렵고 위험한 경험으로 묘사하지 않는다. 사용자가 스스로 할 수 있는 일과 선택할 도움을 제시한다.
  5. 영어 가이드와 모든 언어 지원을 혼동하지 않는다. 실제 지원 언어, 업무 범위, 응답 시간과 비용을 확인할 수 있게 한다.
  6. 추출 후보·확인된 위치·영업 확인·식당 예약·투어 예약은 각각 구분한다. ‘확인 완료’가 무엇의 확인인지 명시한다.
  7. 시제품 표시와 정책 초안은 유지한다. 개발 방식 설명은 고객의 판단에 필요한 제한 안내로 줄인다.

기능 보완 과제 — 문구만으로 해결하지 않는 부분

  • 장소의 한글명·로마자 표기와 복사 가능한 주소: 현지 표지판·기사·지도 검색에서 같은 장소를 식별하도록 실제 장소 데이터 연동 시 설계한다. 현재 후보 화면에는 한글 이름·주소만 표시된다.
  • 영업시간·휴무·예약 필요 여부·예약 경로: 데이터 출처와 갱신 시점이 필요하다. 현재 지도 핀만으로 방문 가능성을 보장하지 않는다.
  • 실제 경로·역 출구·만남 사진: 지도·운영 확인이 필요하다. 현재 이동시간과 만남 장소는 예시다.
  • 해외 카드·결제 통화·환율·수수료·환불 반영 기간: 결제 공급자와 출시 국가 확정 후 작성한다. 현재는 원화 표시와 모의 결제다.
  • 다국어 고객지원: 입력 가능 언어와 실제 답변 가능 언어·시간을 분리해 확정한다. 현재 문의는 로컬 저장만 한다.

외국인 대상 사용성 테스트 제안

한국 첫 방문·재방문 여행객을 나누어 5~8명부터 방향을 확인한다. 이는 통계적 검증이 아닌 초기 사용성 점검 제안이다. 설명 없이 과제를 수행하게 하고 표현을 어떻게 이해했는지 질문한다.
